# 优化训练自动保存按运行日志与逐行北京时间

Status: ready-for-agent

日期：2026-10-09。

实施状态：2026-10-10 已按 01–03 完成实现、测试、双轴审查及收尾，见[验收记录](acceptance.md)。

确认依据：用户要求日志默认保存到模型目录、按启动日期时间命名并逐行加时间；Q67–Q72 全部采用推荐，随后确认拆分并授权实施。

## Problem Statement

当前优化训练在终端打印立即刷新的进度，但日志文件依赖使用者额外设置输出重定向。日志与模型产出分开，运行记录不按每次启动自动归档，内容没有日历时间，因此不方便查找某次运行、关联告警与训练阶段，也不方便事后定位中断。

将日志移入模型目录还会与从头训练的目录清理冲突：当前没有 checkpoint 时清空整个目录，可能删除历史日志，甚至删除已经打开的本次日志路径。只给进度消息添加时间也不能覆盖 Python 多行告警与异常堆栈。

## Solution

优化训练入口自动在配置的模型保存目录建立本次日志，文件名为 log-YYMMDD-hhmmss.log，时间取本次启动时刻。日志同时输出到文件和终端，每个物理行以 [YYMMDD-hh:mm:ss] 和一个空格开头，文件和行时间统一为北京时间、24 小时制。

记录训练进度及训练日志生命周期内的 Python stdout/stderr，包括告警和异常堆栈。立即刷新，两侧内容一致；同秒启动产生同名文件时追加，不覆盖旧内容。跨日运行保持原文件名，逐行日期继续反映实际记录时间。

从头训练保留符合本命名格式的历史日志，清理其他旧训练产物；正常恢复保留历史日志。日志创建或写入失败时终止训练并尽可能从终端说明。日志是运行记录，不参与 checkpoint 恢复；模型、样本、指标和速度统计规则继续沿用既有方案。

## User Stories

1. As a 主策略训练者, I want 启动优化训练后自动产生日志文件, so that 我无需另写固定重定向路径。
2. As a 主策略训练者, I want 日志位于模型保存目录, so that 模型和对应运行记录可以一起查找。
3. As a 主策略训练者, I want 每次启动按启动日期时间命名日志, so that 我能定位不同运行。
4. As a 主策略训练者, I want 文件名严格使用 log-YYMMDD-hhmmss.log, so that 目录中的日志有一致格式。
5. As a 主策略训练者, I want 每行开头显示日期和时分秒, so that 我能将进度与告警对应到具体时间。
6. As a 主策略训练者, I want 文件名与行时间固定使用北京时间, so that 更换机器时仍能按同一时区阅读。
7. As a 主策略训练者, I want 使用 24 小时制, so that 时分秒没有上下午歧义。
8. As a 主策略训练者, I want 一次运行跨日后继续写原日志, so that 一次运行的记录保持完整。
9. As a 主策略训练者, I want 跨日后的每行日期仍然更新, so that 行前缀不会固定为启动日期。
10. As a 主策略训练者, I want 文件与终端同时显示进度, so that 保存记录的同时仍能实时观察。
11. As a 主策略训练者, I want 两侧使用相同的行内容和时间, so that 终端与文件不会出现不同解释。
12. As a 主策略训练者, I want 每行输出及时刷新, so that 不必等待缓冲区积累才能看到记录。
13. As a 主策略训练者, I want Python stdout 与 stderr 都进入运行日志, so that 告警和错误不会落在另一份文件中。
14. As a 主策略训练者, I want 多行告警的每行都有时间, so that 后续文本检查不会遇到未标记的告警行。
15. As a 主策略训练者, I want 异常堆栈在退出前完整记录, so that 失败后仍可调查原因。
16. As a 主策略训练者, I want 空行和分段写入正确保留, so that 多行输出不会缺内容或重复时间前缀。
17. As a 主策略训练者, I want 正常恢复创建本次启动的日志并保留过去日志, so that 多次恢复记录可以追溯。
18. As a 主策略训练者, I want 从头训练也保留符合命名格式的历史日志, so that 重建训练时不会丢失之前的失败记录。
19. As a 主策略训练者, I want 本次日志不被从头目录清理删除, so that 可见的文件与正在写入的内容始终对应。
20. As a 主策略训练者, I want 非日志旧产物仍按从头约定清理, so that 新训练不会混入旧模型和 TensorBoard 结果。
21. As a 主策略训练者, I want 同秒同名日志追加而不覆盖, so that 快速重复启动不会丢失原内容。
22. As a 主策略训练者, I want 通过 start/resume 消息区分同文件内的运行, so that 同秒追加仍可识别边界。
23. As a 主策略训练者, I want 日志不能创建或持续写入时明确失败, so that 我不会误以为记录正在保存。
24. As a 主策略训练者, I want 无法确定日志位置时仍看到终端错误, so that 配置或路径问题不会静默失败。
25. As a 主策略训练者, I want 日期时间与耗时统计分开, so that 系统墙钟调整不会影响速度和 ETA。
26. As a 主策略训练者, I want checkpoint 仍是唯一训练恢复依据, so that 日志追加或缺失不会改变恢复位置。
27. As a 主策略训练者, I want 日志开销只发生在实际输出时, so that 不为每个 batch 增加 GPU 同步或文件写入。
28. As a 维护者, I want 日志资源在正常结束和异常退出时正确收尾, so that 重复调用不会留下旧文件句柄或输出流包装。
29. As a 维护者, I want 从公开训练入口验证日志行为, so that 内部组织调整不会破坏测试。
30. As a 主策略训练者, I want 更新后的启动说明使用自动日志, so that 我能直接按说明运行并找到对应文件。

## Implementation Decisions

### I1. 范围与职责

- 本次作用于当前优化训练链路的运行入口和进度输出生命周期。日志支持与训练入口就近放置，继续由既有进度组件生成训练/验证业务字段。
- 提供一个统一的按行时间与双路输出机制，避免进度消息、告警与堆栈各自维护不同时间格式或重复加前缀。
- 普通训练配置中的模型输出目录同时作为日志目录；不新增日志目录、时区、轮转或任意组合的生产配置选项。
- 继续按既有入口方式读取显式配置，相对输出目录使用启动 PWD 解析。更新正常前台/后台调用说明，自动文件是主要日志，不再要求额外固定文件重定向。

### I2. 文件与时间

- 本次训练入口启动时记录一次墙钟启动时刻，以此命名日志；不因准备阶段耗时、恢复 checkpoint 或跨日而改变文件名。
- 文件名严格为 log- 加六位年月日、连字符、六位时分秒和 .log。日期年份取后两位，时间为 24 小时制，精度到秒，不增加毫秒、PID 或编号后缀。
- 每个实际记录的物理行以方括号中的六位年月日、连字符、带冒号的时分秒开始，再加一个空格和原内容。行时间独立取该行记录时刻，不重复使用启动时间。
- 文件与逐行日期都固定使用 Asia/Shanghai。保留现有单调时钟计时，用于 elapsed、近期训练速度、整体速度和阶段 ETA；这两类时钟不互相替代。
- 文件按文本追加方式打开。同一目录同一秒再次启动时写同名文件并保留原内容，既有 start/resume 消息作为运行分界；这不提供并发训练协调或唯一文件名保证。

### I3. 内容与输出

- 文件和终端双写。原 stdout 内容继续对应原 stdout，原 stderr 内容继续对应原 stderr；两者合并进入同一运行文件。正常未发生 I/O 错误时，两侧单条记录的前缀和内容一致。
- 捕获日志生命周期内的 Python stdout/stderr，包括训练阶段、Python 告警、错误和异常堆栈；不保证捕获绕过 Python 流的原生或子进程描述符输出。
- 按物理行处理单次多行写入、分段写入和空行，不能只给多行消息第一行加时间，也不能对同一行的多个片段重复加前缀。收尾处理尚未完成的文本片段，避免丢失内容。
- 完整行及时刷新文件与终端；输出流的 flush 和正常关闭必须把尚未完成的输出正确处理。使用正常文件 flush，不逐行执行 fsync，也不承诺断电时的日志持久性。
- 保持既有进度事件、指标值、触发频率及可恢复位置的含义。日期前缀增加可观察信息，不改变模型或数据进度。

### I4. 目录清理与恢复

- 本规则明确覆盖旧规格中“没有 checkpoint 时清空整个输出目录”的部分：仍清理旧训练产物，但保留符合新固定命名格式的历史日志文件。
- 日志保留依据为约定的文件名，不扫描内容判定身份，不引入日志索引或额外恢复 JSON。名称类似日志的目录不自动成为日志保留对象。
- 本次日志必须在清理过程中保留，或在清理后建立；不得继续写入已被删除路径的文件，也不得在初始化后以截断模式重新打开并丢失早期记录。
- 正常恢复保留历史日志，为本次启动选择启动时间文件；checkpoint 损坏或不兼容时仍直接报错，不能将其当成不存在并清理目录。
- 已完成任务再次启动仍有本次日志和既有完成消息，但不清空模型产物或重新训练。
- 保留现有输出路径保护、设备检查和失败时不提前清理输出的行为。日志创建不能成为绕过这些边界的理由。

### I5. 生命周期与失败

- 配置读取和必要输出范围检查使保存目录可以安全确定之后，建立本次日志；日志机制应覆盖之后的准备、训练、验证、保存及退出。
- 启动/恢复消息应出现在本次文件中，不因清理顺序而遗漏。初始化前暂存的输出如需补写，应保留原记录时间和内容，不重复记录。
- 日志已经建立后的 Python 异常堆栈须在文件关闭前记录。CLI 以失败状态退出，公开运行接口继续传播异常；不能把异常转换为成功返回，也不能重复记录同一堆栈或产生递归日志故障。
- 文件创建、写入或必要 flush 失败时终止，不吞掉错误、不仅提示后继续；尽可能通过仍可用的原始终端说明日志故障。
- 配置不可读、路径尚不能确定、输出路径不安全或文件不可写时，终端仍应能显示失败原因，不猜测其他文件目录作为回退。
- 正常结束、异常、已经完成后启动和有限验收结束都应处理待写片段、关闭自身打开的文件并恢复原始 Python 输出流。既有训练资源收尾产生的 Python 消息也须在日志结束前得到处理。
- 日志故障不额外提交训练进度。此前完整 checkpoint 保留，重新启动从既有可恢复位置继续。

### I6. 性能与兼容

- 日期格式化和文件输出只在实际输出发生时处理。不能为没有日志输出的 batch 增加墙钟读取、GPU 同步、设备轮询或文件操作。
- 继续复用既有日志/TensorBoard 边界的 CPU 指标；模型、优化器、AMP、随机数、样本顺序、验证提交与 checkpoint schema 均不因文本日志变化而改变。
- 文件名、已输出文本、日期和输出流对象不加入训练 checkpoint 或数据集恢复契约；日志文件不是进度恢复依据。
- 不提供本期之外的日志捕获后台进程、全局运行锁、写入重试、异步队列、心跳和日志轮转。

## Testing Decisions

- 主测试边界沿用用户已确认的公开训练运行接口与 CLI：观察临时输出目录中的实际日志、终端 stdout/stderr、返回/退出状态及 checkpoint。没有新增需要再访谈的测试边界。
- 测试验证使用者可观察的行为，不固定内部类名、辅助函数、包装层数量或实现方式。沿用既有 unittest、临时目录、有限任务和系统边界的时钟/文件故障控制。
- 优先扩展现有启动/恢复、完成后启动、保存失败与受控时钟用例，保持 checkpoint/指标行为回归。需要跨进程验证 Python 异常或输出流时使用有限 CLI 子进程，不启动正式长训练。
- 控制墙钟验证确定的文件名和每行前缀、固定北京时间与 24 小时制；让运行跨秒、跨日，确认文件名仍用启动时间，逐行时间更新。控制单调时钟，证明墙钟变化不改变速度和 ETA 的既有口径。
- 通过实际 Python stdout/stderr 产生进度、普通输出、告警、异常堆栈、空行、单次多行输出与分段写入，核对每个物理行恰有一次前缀，内容保留、终端与文件一致并及时刷新。
- 在可控从头目录中放入已命名历史日志、旧训练产物和其他文件，验证日志保留例外、其余既定清理行为以及本次日志没有被删除或截断。恢复和已经完成启动都保留旧日志。
- 固定同秒启动两次，验证同名追加、旧内容未改、start/resume 分界仍在；不要求新增编号或等待。使用不同启动秒验证产生不同文件。
- 从公开入口制造可写日志建立后的训练异常，验证文件含完整时间化堆栈、失败仍传播或 CLI 非零退出、没有虚假完成、旧 checkpoint 保留。配置/输出位置不可用时核对终端错误与无猜测目录回退。
- 在文件系统边界注入创建、写入和 flush 失败，验证程序直接失败而非无日志继续，故障说明仍可读，不发生递归打印、重复异常或资源泄漏。
- 对正常结束与异常后在同一解释器再次调用公开入口，确认原始输出流恢复，后续输出不会继续落入上一运行的文件；检验关闭时待写片段和训练资源收尾信息没有丢失。
- 配置解析与必要路径保护回归仍通过，尤其设备不支持、坏 checkpoint 和受保护路径不会变成从头清理。已有 CUDA 模型与恢复测试继续作为受影响行为回归，具体范围按实现改动选择。
- 日志验证使用隔离产物。普通文本测试不需要反复编译生产模型；需要真实训练确认时只做有限 CUDA 任务，并报告实际范围，不用日志功能作为启动长期训练的理由。
- 规格发布时检查模板、编号、Markdown、状态标签与本地引用；后续实现阶段的实际测试范围与结果见验收记录。

## Out of Scope

- 原训练链路、筛选、预计算、推理或对局评测入口的日志改造；尤其不向 mjai stdout 插入时间文本。
- 原生 Rust/C++ 和编译子进程的底层文件描述符捕获、PTY 重定向或操作系统级输出收集。
- 可配置时区、任意日志格式/路径开关、日志轮转、压缩、归档、数据库和自动删除历史日志。
- 同秒名称加编号、延迟启动或并发训练锁。
- 日志重试、异步写入队列、逐行 fsync、编译心跳、持续 GPU profiling。
- 日志恢复索引、新 checkpoint 字段、改变 checkpoint schema、以日志推进样本游标或检查源码哈希。
- 改变训练目标、优化组合、随机数/样本顺序、指标频率或验证保存语义。
- 自动操作当前训练进程、重启或启动长期任务；清理迁移工具及以前其他功能的历史产物。
