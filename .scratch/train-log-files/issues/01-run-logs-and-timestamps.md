# 01: 正常训练自动保存带北京时间的双路日志

**What to build:** 使用者从公开优化训练入口启动、恢复或检查已完成任务时，自动在模型保存目录获得按启动时间命名的日志，同时在终端看到相同的逐行时间和 Python 输出；从头训练与快速重复启动能够保留既有日志。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

实施状态：2026-10-10 已完成。

**规格覆盖：** I1–I4、I6，以及 I5 中正常日志生命周期；用户故事 1–14、16–22、25–29。

- [x] 日志由公开优化训练入口自动建立，目录使用既有模型输出设置，文件名严格为 log-YYMMDD-hhmmss.log；不增加日志路径、时区或轮转配置。
- [x] 启动时捕获一次墙钟时刻用于命名，统一使用 Asia/Shanghai 和 24 小时制；每行前缀为 [YYMMDD-hh:mm:ss] 加空格，时间取实际记录时刻。
- [x] 文件与终端双写训练进度及日志生命周期内的 Python stdout/stderr；终端保留原 stdout/stderr 去向，文件合并两路内容，正常写入时单条记录的时间和内容一致。
- [x] 单次多行、空行和分段写入均按物理行处理，内容完整，每行只加一次前缀；完整行立即刷新，正常 flush/关闭处理待写片段。
- [x] 跨日仍写启动时选定的文件，逐行日期正常更新；同秒同名追加而不覆盖，保留 start/resume 运行分界，不加后缀或等待。
- [x] 从头训练仅新增“保留符合固定命名格式的历史日志文件”这一清理例外，其他旧产物沿用既定清理；正常恢复保留历史日志，已完成启动有本次日志而不重训或清理模型。
- [x] 本次打开的日志路径不会被清理删除，启动/恢复消息不会因初始化顺序丢失，也不会以截断重开方式损失前面的记录。
- [x] 现有路径保护、设备拒绝及坏 checkpoint 拒绝仍有效；日志创建不能导致原本不该发生的清理。文件打开/写入错误直接传播，不采用吞错后继续的默认 handler 行为；完整失败诊断由 02 补齐。
- [x] 正常结束恢复原始 Python 输出流并关闭自身文件，重复调用不会重复包装或把后一次输出写进前一次日志。
- [x] 耗时、速度和 ETA 沿用单调时钟，日志信息不进入 checkpoint；没有输出的 batch 不增加墙钟读取、文件操作或 GPU 同步。
- [x] 通过公开训练接口/有限 CLI 测试核对文件、双路输出、实际 Python 告警、受控时间、跨日、同秒追加、从头清理、恢复及已完成启动；同步适配受影响的既有日志断言，检查指标含义而不是包装类内部。
- [x] 随票给出正常自动日志的最小使用说明；所有验证使用临时目录或隔离产物，不启动正式长期训练。

**独立验收：** 有限正常任务的终端与磁盘文件都包含带北京时间的阶段记录；重复启动、跨日和目录清理后，旧记录与本次记录均符合规格。

**边界：** 使用就近的日志支持接入现有训练入口，无需先改造其他链路或建立通用日志框架。02 在本票的正常输出能力上完成失败记录和退出行为。
