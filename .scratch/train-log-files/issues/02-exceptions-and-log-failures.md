# 02: 完整记录训练异常并在日志失败时可靠退出

**What to build:** 训练或初始化失败时，使用者能够从本次日志和终端查到逐行带时间的 Python 错误堆栈；日志本身无法保存时训练明确失败，原 checkpoint 仍是恢复依据，输出资源得到正确收尾。

**Blocked by:** 01 — 正常训练自动保存带北京时间的双路日志。

**Status:** ready-for-agent

实施状态：2026-10-10 已完成。

**规格覆盖：** I3、I5，以及 I4/I6 的错误边界；用户故事 13–16、23–24、26、28–29。

- [x] 日志建立后的 Python 异常堆栈在文件关闭前完整记录，包含所有物理行和空行；文件与可用终端均保留正确时间前缀，避免重复堆栈或重复前缀。
- [x] CLI 以失败状态退出，公开运行接口仍传播异常，不将错误转换为成功返回，也不输出虚假训练完成或保存成功。
- [x] 配置无法读取、日志位置尚不能安全确定或目标不可写时，仍从可用终端报告失败，不猜测另一日志目录，也不绕过输出范围保护。
- [x] 文件创建、写入和必要 flush 失败均终止训练，并尽可能使用仍可用的原始终端说明；不存在吞错后继续、递归日志错误、重试或异步写入队列。
- [x] 日志故障不触发额外训练进度提交；验证/保存失败后依然保留上一次完整 checkpoint，不把日志位置当作恢复位置。
- [x] 正常异常传播、初始化异常和有限任务收尾均关闭自身文件并恢复原始输出流；既有训练资源收尾期间的 Python 消息在日志关闭前得到处理。
- [x] 通过公开入口和有限 CLI 子进程制造实际 Python 异常，检查磁盘内容、终端输出、异常/退出状态、旧 checkpoint 及输出资源；不只测试私有格式化函数。
- [x] 在文件系统边界分别注入创建、写入和 flush 故障，证明训练不会无日志继续，并验证错误传播不被异常记录或资源关闭再次掩盖。
- [x] 异常之后在同一解释器再次运行，确认没有旧句柄或旧输出流包装残留，待写片段得到处理，后续输出不会落到上一运行文件。
- [x] 回归坏 checkpoint、设备不支持及受保护路径的行为；补充错误定位与日志失败说明，并明确底层原生/子进程描述符输出不在捕获承诺内。

**独立验收：** 一个受控训练异常产生完整时间化堆栈并失败退出；文件故障产生可读终端错误，之前完整 checkpoint 保留，之后可正常重新调用入口。

**边界：** 不引入 OS 级输出重定向、日志恢复索引、后台日志服务或自动训练重启。
