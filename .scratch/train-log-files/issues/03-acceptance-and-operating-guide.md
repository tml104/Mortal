# 03: 验收自动日志并更新训练操作说明

**What to build:** 使用者得到经过有限实际训练验证的自动日志功能和准确的前台/后台启动、查看日志及故障说明；维护者能够据记录确认日志改动没有改变训练恢复和指标行为。

**Blocked by:** 02 — 完整记录训练异常并在日志失败时可靠退出。

**Status:** ready-for-agent

实施状态：2026-10-10 已完成。

**规格覆盖：** Testing Decisions、Further Notes 和 I1–I6 的贯通验收；用户故事 25–30。前序票的行为测试随各票执行，不推迟到本票。

- [x] 使用隔离目录和有限训练工作量串起启动、准备、训练、验证、保存、结束及恢复，确认每次日志自动落在模型目录，终端与文件时间一致，阶段信息完整。
- [x] 在现有受控时钟与恢复用例中确认墙钟变化不改变 elapsed、速度或 ETA，checkpoint schema、样本游标、未输出指标窗口和 TensorBoard 口径保持既定含义。
- [x] 执行受影响的日志、配置、路径保护和训练恢复回归，完成必要语法/导入检查；记录实际命令、通过/跳过项及限制，不以文本测试替代需要执行的训练路径。
- [x] 核对日志写入只由实际输出触发，没有逐 batch 新增设备访问、同步或文件操作；不为此次日志功能运行生产模型的大型性能网格。
- [x] 更新正常前台/后台启动和查看说明，明确模型目录中的自动日志是主要日志，原固定外部重定向不再是必要步骤；命令符合仓库根目录启动约定。
- [x] 说明北京时间、启动文件名与逐行时间、跨日、同秒追加、历史日志保留、失败终止及 Python 捕获边界；不新增日志路径或时区开关。
- [x] 形成验收记录并核对最终改动范围，保留用户既有数据、配置和历史产物；如本轮产生一次性验证脚本，保留必要参数与结果后清理，永久回归测试继续保留。
- [x] 正式训练启动或重启不作为本票自动动作；确需有限 CUDA 验证时先核对当时进程与配置，使用隔离输出，并明确报告实际验证范围。

**独立验收：** 有限实际运行可按操作说明找到并阅读本次日志，恢复与错误路径已有证据，相关回归通过，使用说明和清理后的代码引用一致。

**边界：** 不扩展为其他入口的日志改造、迁移工具清理或长期训练托管。
