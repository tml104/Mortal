# 02: 有界并行校验并按文件顺序提交

**What to build:** 用户可以同时校验多份牌谱以提高吞吐；即使 worker 乱序完成，坏谱移动、JSONL 报告和恢复游标仍由主进程严格按文件名顺序提交，并且等待中的全部工作不会超过配置上限。

**Blocked by:** 01 - 通过 spawn 单 worker 完成轻量筛选。

**Status:** ready-for-agent

- [x] 默认配置使用 8 个 worker、每 worker 2 个 Rayon 线程和 16 个最大在途任务，并允许用户覆盖三项参数。
- [x] 调度器允许后方文件先完成，但只有从下一个待提交文件开始连续就绪的结果才会触发移动、报告和游标推进。
- [x] 已派发未完成的任务与已完成但等待前序文件的结果共同计入最大在途窗口，任何时刻都不超过配置值。
- [x] 只有主进程执行文件移动、报告追加和进度提交；worker 返回的数据不包含 observation、Gameplay 或其他大对象。
- [x] `commit_every` 的提交频率、split 末尾余量提交、train 完成后切换 val、val 全部提交后标记 complete 的语义保持不变。
- [x] 通过可控乱序完成的入口级测试验证隔离集合、报告顺序、游标顺序和窗口上限，而不依赖内部 Future 容器的具体实现。
