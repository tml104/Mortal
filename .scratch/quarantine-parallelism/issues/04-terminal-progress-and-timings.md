# 04: 展示筛选进度与分阶段耗时

**What to build:** 用户运行长时间筛选时，可以在每个进度提交周期从终端看到当前 split、整体进度、吞吐、预计剩余时间、隔离数量、当前游标和各校验阶段的耗时，从而判断任务是否正常及瓶颈所在。

**Blocked by:** 02 - 有界并行校验并按文件顺序提交。

**Status:** ready-for-agent

- [x] 每顺序提交 `commit_every` 份牌谱后输出一次进度，最后不足一个周期时也输出对应的最终状态。
- [x] 每条进度包含 split、已处理数量、总数、百分比、累计隔离数、平均处理速度、ETA 和当前相对路径游标。
- [x] 每条进度包含 gzip 读取、Python 规则检查和 libriichi 样本适用性检查的累计平均毫秒/文件，并明确这些并行阶段耗时不能相加解释为 wall time。
- [x] 用于展示的总数和已处理位置从源目录、隔离目录与恢复游标计算，不参与决定恢复正确性。
- [x] 捕获公开筛选入口的终端输出验证字段和更新频率；低样本数、跨 split 和恢复场景仍能得到有意义的输出。
- [x] 持久化进度继续只包含 schema、状态、split 和相对路径游标，不新增速度、ETA、计数或阶段耗时字段。

## Comments
