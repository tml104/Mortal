# 03: 在并行异常后保持可恢复边界

**What to build:** 并行筛选遇到明确的数据错误时继续按序隔离，遇到程序错误、worker 退出或用户中断时停止运行并保留最后一次已提交边界；重启后可以从现有 incomplete 进度自然重查所有未提交文件。

**Blocked by:** 02 - 有界并行校验并按文件顺序提交。

**Status:** ready-for-agent

- [x] 只有既有的明确输入错误会变成可隔离结果；其他异常和 worker 异常退出会传播到主进程并使命令失败。
- [x] 首个未知异常出现后停止派发新任务，取消尚未开始的任务，并在进程池得到清理后重新抛出原始失败。
- [x] 故障文件之后即使已有 worker 结果，也不会移动文件、追加报告或让进度游标越过故障边界。
- [x] 提前读取但尚未顺序提交的文件保持在源目录，重启时依据原游标再次校验，不需要持久化内存结果或 buffer。
- [x] 现有串行版本写出的 schema v1 incomplete 进度可以直接恢复，包括当前停留在 train 的非空相对路径游标。
- [x] 入口级测试覆盖输入错误、未知异常、慢前序与快后序、恢复重查、隔离目标冲突和用户中断的外部可观察结果。
