# 04: 优化编码与默认线程并保持旧数据兼容

**What to build:** 用户使用已筛选的稳定输入执行预计算时，采用实测较快的默认参数并减少编码中的大副本和重复扫描；生成的六元样本可由现有 reader 精确读取，已有 chunks 与恢复进度继续有效。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [x] 默认参数采用 `rayon_threads=16`、`torch_threads=1`、`file_batch_size=4`，仍允许合法覆盖。同步解析器、示例及本链路实际配置的受影响键，保留用户路径、配额及其他运行设置；Rayon 在首次使用 Rust 并行运行时前生效。
- [x] 整行相同的二值和连续通道直接提取第一列；逐牌通道连续提取，已知二值尽早转 uint8，减少整行副本及后续 reshape/转换复制；继续按固定语义布局编码。
- [x] 筛选入口继续完整检查整行一致性、观测二值取值和 NaN/Inf；编码省去这些重复观测逐值检查，不删除筛选使用的完整校验能力。
- [x] 编码仍检查 observation 形状/dtype、字段长度、非空 chunk、动作/标签/折扣步数范围、二值 mask、动作属于 mask 和有限奖励等必要约束，错误直接终止；不加入自动修复或新的防御性校验流程。
- [x] 对符合既有语义的输入保持 float32 观测、float64 奖励、字段/样本/位顺序、格式头、schema、字节序与 Zstd 等级；保留 CPU float64/eval 的奖励推理方式及设备解码的 PyTorch 延迟导入。
- [x] 用优化前参考结果或独立预期验证公开编解码接口的六元精确往返，覆盖四类语义通道；复用筛选回归证明观测语义错误仍在前置阶段拒绝，不将临时性能脚本用作生产编码器。
- [x] 通过公开生成入口在临时数据上验证正常分块与文件内恢复，新旧 chunks 可被现有 reader 混合读取，旧进度与生成 ID 无需迁移；改变线程参数不触发重建，也不回读全部历史 chunk 验证身份。
- [x] 保留小型 CPU 编解码及轻量导入回归，环境支持时验证设备解码；只针对临时数据验证，不启动正式训练或继续用户的全量预计算。
