# 02: 准确显示牌谱完成比例、恢复速度和 ETA

**What to build:** 用户从头生成或从文件内断点恢复时，能看到准确的完整牌谱完成比例、本次吞吐及当前 split 的预计剩余时间，能够区分已有成果和此次新增的工作。

**Blocked by:** 01 — 在 chunk 提交边界输出可配置的进度日志。

**Status:** ready-for-agent

- [x] 在已建立的进度日志中补齐完整提交牌谱数/总数、百分比、本次运行耗时、牌谱速度、样本速度和当前 split 的 ETA；文件总数复用现有有序输入，不为每条日志重新扫描目录或预先生成全部样本。
- [x] 一份牌谱只有全部样本进入成功提交的 chunk 后才计作完整完成；一谱跨多块、多谱拼一块和 buffer 中的未提交样本不会使完成比例提前增加。
- [x] 旧 incomplete 状态可直接恢复，正确区分游标位于谱内或恰好位于谱末；正常重读游标牌谱和跳过已提交样本不虚增本次完成量。
- [x] 累计 chunk、样本和磁盘成果继续衔接旧状态；速度仅使用本次新增提交样本和新增完成牌谱除以本次耗时，不能将历史累计成果除以重启后的短时间。
- [x] ETA 基于当前 split 的剩余牌谱和可用速度；无速度依据时显示不可估算，空 split、尾块、切换 split 和完成时不出现除零、无穷大或混用 train/val 口径。
- [x] 使用单调时钟；显示统计只存在于本次运行内存与终端，不改写已有源文件总数字段的用途，不新增恢复字段、运行时源码哈希或输入证明机制。
- [x] 在公开运行入口使用可独立计算样本数的临时牌谱与受控时间，核对文件完成数、速度、ETA 及重启后的计数；验证日志周期变化和失败恢复不会改变最终样本序列。

## Comments

不要求日志预知全量样本数，也不承诺固定完成时间。验收关注统计口径和数据提交边界，不锁定格式空格、私有计数对象或实际机器运行速度。
