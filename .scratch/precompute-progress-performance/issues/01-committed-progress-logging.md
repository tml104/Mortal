# 01: 在 chunk 提交边界输出可配置的进度日志

**What to build:** 用户通过现有预计算入口从头生成或恢复时，能立即看到生命周期提示，并在 chunk 与恢复进度成功保存后看到真实的已提交成果；日志频率可配置，写盘失败不会被误报为成功。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [x] 增加正整数运行参数 `log_every_chunks`，默认 1；省略该键的旧配置仍可加载，自定义合法值生效，零、负数、布尔值和其他非整数被拒绝。同步本链路示例与实际配置的此项，保留原有路径、配额及其他值。
- [x] 启动/恢复、目录扫描开始、split 切换、完成和已完成后再次启动均有清楚的日志；这些事件不受周期限制，已完成的数据集退出时不进行新的生成。
- [x] 周期按本次成功提交的 chunk 计数，尾块同样计入；split 结束时不足一个周期也能看到最后成果，所有输出及时 flush，并保留最终结果摘要。
- [x] 基本进度显示当前 split、累计已提交 chunk 和样本数、C/D 已提交用量与配置预算、恢复游标及样本 offset；明确计数对应当前 split 或全数据集。
- [x] 只有 chunk 发布与进度原子保存均成功后才报告新增成果。文件写入或进度提交失败时直接抛出异常，不输出失败 chunk 的成功日志或整个任务的完成消息，即使内存中的状态对象已提前变化。
- [x] 恢复时展示已有累计成果；性能展示不新增恢复 JSON 字段、不改变生成 ID、schema 或游标含义，buffer 与提前生成的数据不计为已提交。
- [x] 通过公开 `run_precompute` / CLI 和现有临时数据生成用例，验证默认/自定义周期、尾块、空 split、生命周期、flush、旧进度恢复展示，以及“文件已发布但进度未提交”的日志边界。
