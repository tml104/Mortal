## 2026-09-30 从源码确认的原始状态

- `precompute.py` 在 `run_precompute()` 全部返回后才打印最终 JSON，生成过程中没有周期日志；本次看不到日志是现有实现的行为。
- `storage.commit_chunk()` 先原子发布 chunk，再原子提交进度 JSON；只有调用成功返回，才能对外报告该块已提交。
- 每个 chunk 默认包含 16,384 条样本；源牌谱可能跨越 chunk，恢复游标包含相对路径和样本 offset。
- `source_file_count` 目前只在 split 结束时填写，运行中为 0 不表示没有处理牌谱。日志可使用已有排序文件列表取得总数和位置，无需反复扫描或修改该字段含义。
- 生成前不知道全量样本数；仅凭已生成的 chunk 不能算出精确的最终 chunk 总数或样本完成百分比。
- 修改源码不会让已经运行的 Python 进程获得新日志逻辑；实现完成后须在新启动或恢复进程中生效。

Q39 已确认新增可配置 `log_every_chunks`，默认 1。启动/恢复、目录扫描开始、split 切换和完成日志不受该周期限制，最后不足一个周期也输出；输出立即 flush。只有 chunk 和进度 JSON 均成功提交后，才报告该块已提交。它是处理边界上的日志，长时间阻塞的单次调用中不提供定时心跳。

Q40 已确认显示当前 split、完整提交牌谱数/总数及百分比、累计已提交 chunk 和样本数、本次运行耗时、样本/牌谱速度、当前 split 的估算 ETA、C/D 已提交字节/预算以及游标和 offset。恢复后的累计数保留，吞吐仅使用本次新增工作除以本次耗时，避免把旧任务成果计入重启后的速度。游标所在牌谱未完全进入已提交 chunk 时，不算作完整完成；buffer 中尚未提交的样本不计入已提交成果。性能统计仅在终端展示，不新增恢复 JSON 字段。

Q41 最终确认采用五段：Rust/libriichi 提取、GRP 奖励推理、Python 样本整理、编码压缩、写盘与进度提交。输出本次运行各段的累计耗时。五段方案取代此前讨论的“生成、编码、提交”三段方案，用于明确区分提取和奖励推理的成本。

Q42 已确认：完整观测语义检查继续保留在筛选阶段；编码阶段省去整行一致性、二值取值及 observation NaN/Inf 的逐值重复检查，保留形状、dtype、字段长度、动作和标签范围、合法 mask、有限奖励等现有必要检查。该选择依赖既有的“已通过筛选且输入内容、生成语义保持稳定”约定，接受不再二次检测观测语义异常的取舍。不得因此删除筛选所需的完整校验函数。

Q43 已确认：默认 `rayon_threads=16`、`torch_threads=1`、`file_batch_size=4`，三项继续可配置。正式实现已同步配置解析默认值、示例配置、实际配置和相关说明。

Q44 已确认：整行相同的通道直接取第一列；逐牌通道采用连续布局提取；已知二值数据尽早转为 uint8，以减少后续 reshape 和转换产生的大副本。连续观测保留 float32、奖励保留 float64；chunk 格式、样本顺序和既有恢复语义保持兼容。该布局优化本身不依赖取消完整检查；用户此次同时接受 Q42 与 Q44。

此次确认形成正式方案，不新增 ADR。正式 spec 和五张任务已发布并进入实现，完成证据保留在对应任务及验收记录中。

## 后续验证建议

正式规格沿用公开 `run_precompute()` / CLI 为主要测试边界，验证启动/恢复、提交成功、跨文件/跨 chunk、尾块、split 切换、已完成退出和提交失败时的日志；既有数据产物与进度结构保持兼容。捕获输出并使用受控计时验证恢复后的速度和文件完成数，避免以长时间真实运行验证日志功能。辅助复用 codec 公开编解码与筛选测试边界，覆盖新旧精确输出和前置语义检查保留；具体验收列于正式规格的 Testing Decisions。

## 新增效率需求与实验结果

用户已自行停止 precompute.py，并要求把效率和线程网格纳入此次方案。正式状态停在 train 的 739 个 chunk、12,107,776 条样本，游标为 `paipu-mjai-2019/20190210-0276.json.gz`、sample_offset=325；独立筛选进度为 complete。

已完成 Rayon `{1,2,4,8,12,16}` × PyTorch `{1,2,4}` 的 18 组短测，以及文件批次对照和 128 份真实 D 盘对照。完整方法、结果与可复测产物见 [性能实验报告](precompute-performance.md)。原配置约 1,556 样本/秒；仅调整为 16/1/4 约 2,106；连续布局、减少复制并省去重复观测检查的临时版本约 2,890。所有已测组合的样本字段和 float64 奖励均与原配置逐位一致。

Q42 的已确认取舍依据：保留检查的优化布局对照约 2,447 样本/秒、6.27 GiB；省去重复检查的版本约 2,870–2,910 样本/秒、5.1 GiB。

Q41 的五段划分来自分段测量：Rust 和编码是主要成本，GRP 推理占比较低，分开展示更便于后续定位效率问题。

Q43 的配置取舍依据：较长对照中的 12/1 也很接近 16/1，不能断言 16 在所有负载下都稳定领先；此次选择实测重复成绩略快的 16/1，并保持批次为 4 控制内存。

Q39–Q44 已全部确认。本轮方案范围为日志、线程调优和编码优化，保持奖励模型的 CPU float64 语义；有界生成/编码流水线与新增多进程架构尚未采用。
