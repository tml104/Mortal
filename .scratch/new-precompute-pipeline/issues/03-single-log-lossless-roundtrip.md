# 03: 单份牌谱生成六元样本并完成无损缓存往返

**What to build:** 一份已知有效牌谱可以经过 libriichi 和冻结的 Transformer-GRP，得到完整六元训练样本，保存为新格式 chunk，再在 CPU 精确还原全部字段。通过程序接口和临时产物验收这条完整路径，不增加额外产品入口。

**Blocked by:** 01 — 独立扫描并隔离协议损坏的牌谱（使用其独立配置、限定导入和有序输入基础）。

**Status:** ready-for-agent

- [x] 使用 v4、四家、无 Oracle、无增强的提取方式，合法空玩家视角贡献零条样本。
- [x] 使用已确认的冻结 GRP 配置进行 CPU float64/eval 推理；同谱四家共享预测结果，按效用差生成局奖励，终局使用真实顺位。
- [x] 六元样本的折扣步数、局奖励与局结束后顺位含义正确；gamma 留给训练阶段应用。
- [x] 在共用格式中定义四类固定语义、必要约束和二进制头部；观测保留 float32，奖励保留 float64，二值字段按位打包，其余字段采用已确认位宽。
- [x] 采用 Zstd level 1，载荷不保存逐样本来源坐标；编码时不扫描实际值来重新分类通道。
- [x] 从真实小牌谱形成的 chunk 及覆盖各类通道的构造样本，CPU 往返后逐字段精确相等；标签测试包含可独立计算的奖励和局边界案例。
- [x] 不兼容版本、截断载荷等格式错误直接抛出；样本生成异常或非有限奖励直接停止，不静默丢样本或隔离文件。
- [x] 仅继续使用 libriichi 与既有模型定义，不导入旧预计算、奖励或训练实现。
