## Problem Statement

主策略训练已经使用预计算样本，能够跨 chunk 拼 batch、保存 checkpoint 并恢复，但当前执行仍存在大量小 GPU kernel 的提交与数据排列转换开销。显存尚有余量，并不意味着持续增大 batch 就能提高吞吐；此前实验中，部分更大的 batch 反而更慢。用户希望结合已经取得实测依据的编译、CUDA Graph、batch 2048 和卷积布局改造，提高现有硬件上的训练效率。

训练已经进行到中途。当前恢复契约包含 batch size，不能通过直接修改配置无缝切换；Conv1d 改为 Conv2d 后，权重及 AdamW 状态的形状也发生变化。用户需要保留已有学习成果、随机状态与样本进度，通过明确的迁移进入独立优化链路。

现有训练缺少持续的终端进度反馈。用户无法直接区分模型准备、训练、离线验证与保存，也难以判断当前已处理位置、真正可恢复的位置和本次运行速度。新模型采用原生 Conv2d checkpoint 后，还需要能够实际使用它进行普通 mjai 推理与独立对局评测。

## Solution

新增独立优化训练链路，保留既有链路作为当前基线。优化链路使用高度为 1 的 Conv2d 和 channels_last，默认 batch 为 2048，完整 batch 使用静态编译与 reduce-overhead/CUDA Graph；不足一个 batch 的真实样本继续用同一组权重执行普通前向和训练。

提供显式旧预计算 checkpoint 到新 Conv2d checkpoint 的迁移操作，写入新的训练产出目录。保留模型、BN、AdamW、AMP、必要随机数状态、种子、epoch 与样本进度；学习率暂保持 1e-4，继续消费原 chunks。迁移完成和开始续训是两个独立操作。

新训练在启动、准备、首批执行、训练、离线验证、保存及完成阶段输出立即刷新的单行日志。保留累计 batch 的 TensorBoard 横轴，默认每 50 批记录指标、每 500 批验证固定子集并保存，每个 epoch 末执行全量离线验证。

新增普通 mjai 推理及独立 Mortal 对 Mortal 一对三评测入口，只加载新 Conv2d checkpoint。评测默认 400 场半庄、每批 64 场，使用可配置种子和双方执行设置；每批保存基本排名结果，默认不保存牌谱。

## Implementation Decisions

### I1. 模块与依赖边界

- 提供独立优化训练、显式迁移、普通 mjai 推理、独立一对三评测四项操作。训练循环、配置、恢复、迁移、离线验证与终端日志由新训练链路负责；不直接导入旧训练目录中的运行模块。
- 原训练链路继续保留，本期不回填新日志，也不增加统一模式开关或删除旧实现。两种训练执行方式由独立入口承载。
- 复用稳定的公共数据集描述与 codec、libriichi、MortalEngine。新模型定义和新 checkpoint 加载由三个新入口共享，辅助实现按入口职责就近组织。
- 新训练实现自身的读取编排，遵守既有 reader 的确定性顺序与恢复行为；这不要求复制牌谱处理、规则引擎或压缩实现。
- 各入口独立读取所需配置；训练、推理、评测不要求提供无关的筛选或奖励模型配置。使用直接脚本启动方式，配置路径显式传入，相对资源路径按启动 PWD 解析；沿用仓库根目录启动约定。

### I2. 模型表示和训练目标

- 观测版本继续为 v4，外部输入保持每个样本原有的通道与 34 张牌维度，动作空间及 mask 语义保持不变。新主干在内部将观测表达为高度为 1 的二维输入，卷积使用 Conv2d，并贯穿使用 channels_last 内存格式。
- 迁移卷积权重时，将形状 `[out, in, k]` 对应为 `[out, in, 1, k]`；卷积核、padding 等仅增加高度为 1 的等价表示，不改变牌维的计算含义。通道注意力对应调整空间归约和广播，展平后的特征次序与原网络对应。
- BN 改为匹配二维输入的实现，保留其参数、running mean/variance、累计计数、momentum 与 epsilon。训练/验证模式切换、冻结 BN、重置统计等公开行为保持对应。
- 继续训练 Brain、DQN 和 AuxNet。DQN 与辅助顺位目标不改变，不引入目标网络、新奖励或新的模型宽深选择。模型默认 192 通道、40 个残差块，BN 不冻结，结构参数仍可配置；迁移时由源状态约束对应结构。
- DQN 目标继续为折扣因子按折扣步数乘以已冻结的局奖励；DQN 损失为二分之一均方误差，CQL 为合法动作 Q 的 logsumexp 均值减所选动作 Q 的均值，辅助损失为局结束后顺位的交叉熵。总损失按既有权重相加。
- 继续使用 AdamW，Linear 与 Conv2d 的 weight 进入原有权重衰减组，其余参数沿用无衰减组。参数组必须与迁移的优化器状态对应，不能只替换卷积类型而遗漏衰减。
- 默认 gamma=1.0、CQL 权重=5.0、顺位损失权重=0.2；AdamW 学习率=1e-4、betas=(0.9, 0.999)、epsilon=1e-8、weight decay=0.1。这些沿用当前方案并保持可配置；本次迁移不顺带修改训练目标。

### I3. 固定优化执行组合

| 项目 | 默认/约定 |
| --- | --- |
| 训练设备 | cuda:0 |
| batch size | 2048，可配置 |
| 模型布局 | 高度为 1 的 Conv2d + channels_last |
| 完整 batch | 静态 torch.compile，reduce-overhead / CUDA Graph |
| 不完整 batch | 同一组原始模型权重的 eager 路径 |
| 混合精度 | FP16 AMP，保存 GradScaler 状态 |
| 编译线程 | 2，可配置 |
| 其他线程 | 必要的 PyTorch/Rust 线程参数可配置；未显式设置时沿用运行库默认，不从预计算配置偷取线程值 |
| 数据预取 | 沿用单块 CPU 预取及按 batch 在目标设备解码，可配置 |
| cuDNN benchmark | 沿用开启配置 |

- 完整训练和完整验证 batch 均使用固定组合；验证先进入 eval/inference_mode，小 batch 按实际形状使用同权重 eager。验证限额切出的不完整 batch 也适用该规则。
- 明确标记每次训练和验证迭代的 CUDA Graph 步边界，保证训练、验证、尾 batch 和下一次完整 batch 之间的张量生命周期正确。统计累加不得在下一次 replay 覆盖输出后再读取旧结果。
- compiled 包装与 eager 路径共享原始模型对象和参数，不能生成两套独立权重、优化器或 BN 统计。保存的是原始模型的原生二维状态，不保存编译包装前缀或 CUDA Graph 对象。
- 本期提供固定优化组合，不增加任意排列所有底层优化的生产开关，不提供新 Conv2d 模型的第三套纯 eager 生产训练模式。完整 batch 的编译失败直接抛错；明确的小 batch 分支不等于异常时自动降级。
- 编译和捕获不执行额外、未计数的训练更新。首个真实 batch 承担懒编译/捕获成本，并正常推进一次真实训练批次；初始化不能改变恢复后的 BN、AdamW、AMP 或随机状态。

### I4. 数据顺序、batch 与进度

- 仅消费已完成预计算的数据集记录及其 chunks，不重新调用 GameplayLoader 或顺位预测模型展开牌谱和计算奖励。保持无损解码后的六元样本语义与精度。
- 保持既有由主种子、epoch、split、chunk 标识派生的两级乱序规则，包括现有派生算法和随机数生成器；新的读取实现须与旧实现生成相同逻辑样本序列。batch size 不参与该顺序。
- 按当前 epoch 已消费样本数直接定位剩余序列；chunk 边界不等于 batch 边界。1024 改为 2048 后从同一样本位置重新组批，不重放已提交样本，也不跳过剩余不足新 batch 的样本。
- 保留每轮最后的小 batch，执行正常反向及 AMP/优化器步骤。累计样本数按实际样本量增加，累计 batch 每处理一批增加一次；AMP 可能跳过溢出更新，因此 batch 数不是严格的参数更新次数。
- 历史 batch 计数完整继承，不因 batch 翻倍而减半；累计样本数不能统一由累计 batch 乘新 batch size 推导。
- 目标 epoch 数继续可配置，当前目标 30。迁移保留已完成轮次与轮内位置，30 表示总目标，不表示迁移后再追加 30 轮。目标已完成时明确报告并退出，正常提高目标轮次后可以继续。

### I5. 原生 checkpoint、从头训练与正常恢复

- 用一个原子保存的 checkpoint 同时持久化新模型格式及结构信息、Brain/DQN/AuxNet、AdamW、AMP、必要随机数状态、主种子、数据集及训练语义契约、已完成 epoch、当前 epoch、轮内已消费样本、累计样本、累计 batch、未输出指标窗口及最近一次验证信息。
- 新格式具有明确的 schema/模型表示标识，不能与旧一维格式仅凭形状猜测混用。模型元信息足以在没有训练配置、chunks 和优化器实例时构造推理所需的 Brain 与 DQN。
- 保持安全加载 `weights_only=True`，严格加载模型权重；缺字段、损坏或不兼容状态直接报错。保留必要的数据集生成 ID、模型、损失、优化器、batch、AMP 和验证语义一致性检查，不增加源码或逐文件哈希。
- batch 的语义变化通过显式迁移进行，普通恢复不自动升级旧格式。日志周期、线程等运行设置不作为重新初始化训练的理由；目标 epoch 的合法延长沿用既有恢复能力。
- checkpoint 不存在时按既有从头训练约定清理配置中本次训练专用产出目录，随机初始化，生成并持久化主种子和初始状态，再进行首次训练。清理仅限 artifacts 下明确的训练子目录，配置、源权重和数据不能位于将清理的范围内；损坏 checkpoint 不按不存在处理。
- 正常恢复先构造并装载模型与优化器等状态，再确保必要 CPU/CUDA 随机状态在首个真实训练步骤前恢复。未输出指标窗口继续累计，运行耗时与速率计时重新开始。
- 周期或 epoch 验证成功后原子替换 checkpoint；验证或保存失败时保留上次已提交状态并抛错。最后已保存 batch 只能在替换成功后推进，不能由内存进度推断保存已经完成。
- TensorBoard 继续使用累计 batch，正常恢复的 purge 边界为已保存 batch 加 1。新目录不复制旧 TensorBoard 历史，也不新增另一套以样本为横轴的事件。

### I6. 显式迁移

- 迁移输入仅为当前旧预计算链路的完整 checkpoint，输出为新优化链路的可恢复 checkpoint；不支持任意原通用 Mortal 格式，不做逆向转换。
- 源 checkpoint、源产出目录与已有 chunks 只读保留。迁移目标必须是新的或空的专用产出目录，不覆盖非空目标；迁移本身不启动训练。
- 映射所有模型参数、BN 状态以及每个参数对应的 AdamW 状态。卷积参数的一阶、二阶矩增加相同的高度维度；优化器 step 等标量、非卷积参数及其状态保持对应，不清空动量或重建历史。
- 保留 AMP、必要随机状态、种子、epoch/样本/batch 进度与数据集身份。输出契约明确使用原生 Conv2d、新 batch 与新执行设置，沿用已确认的模型、损失、优化器及验证语义；不能把契约整体替换成目标配置后忽略不允许的变化。
- 只清空迁移前未输出的训练展示指标窗口；正常同格式恢复不清空它。保留的旧验证结果须保持其原始归属，不能作为新实现已经完成验证的证据。
- 迁移汇报源与目标、保留的训练位置、清空的展示窗口、下一日志/保存边界。新推理或评测需要旧预计算模型时复用此迁移能力，不另实现运行时旧模型加载或额外权重导出。
- 迁移后样本顺序可以保持，但 batch、算子和浮点执行发生变化，不承诺后续参数轨迹与旧训练逐位相同。

### I7. 指标、验证与保存周期

| 配置 | 默认值 | 触发口径 |
| --- | ---: | --- |
| log_every_batches | 50 | 累计训练 batch 取模 |
| save_every_batches | 500 | 累计训练 batch 取模，先固定子集验证再保存 |
| validation_samples | 131072 | 固定验证顺序的前缀；小验证集使用全部可用样本 |
| validation_seed | 0 | 固定验证顺序，不随训练 epoch 改变 |
| epoch 结束 | 每轮 | 全量 val，然后提交完成状态 |

- 例如从累计 batch 123456 迁移，下一日志和周期保存均为 123500，即新增 44 批后触发；不另建从迁移或本次启动起算的周期。
- 训练和验证保留已有 loss、DQN loss、CQL loss、rank loss、rank accuracy、Q 均值与 target Q 均值。按真实样本量加权，小 batch 不与完整 batch 等权。学习率继续写入训练指标。
- 训练指标是窗口均值，不冒充整轮平均；迁移会清空窗口，正常恢复保留。终端尾部补齐不应悄悄改变常规窗口跨 epoch 累计的语义。
- 验证不更新参数、优化器、BN 或训练游标，结束后恢复先前训练模式和 BN 冻结设置。固定子集与全量验证使用相同计算规则，末尾不足一个 batch 时按真实数量处理。
- epoch 尾部与周期保存重合时只做一次全量 epoch 验证及保存，不重复先跑固定子集。训练数据处理到 100% 后仍可能处于验证/保存阶段；只有全量验证与状态提交完成才能报告该 epoch 完成。

### I8. 终端进度与性能统计

- 采用普通单行 `key=value` 并立即 flush。覆盖启动/恢复、模型准备、首次真实 batch 开始/结束、训练周期、验证开始/进度/结束、checkpoint 保存成功、epoch 完成、全部完成和启动时已经完成。
- 训练周期复用 TensorBoard 的日志边界，验证按局部 batch 的相同配置间隔输出，阶段尾部补齐。阶段事件不受周期限制；不为阻塞的编译或 Rust 调用添加后台心跳线程。
- 启动信息包含生效的设备、batch、优化组合、线程设置和恢复基线。懒编译完成前不能因包装器构造返回就宣称编译完成；首批结束后才报告该批执行成功。
- 训练进度包含当前/目标 epoch、轮内已处理/总样本及百分比、累计样本、累计 batch、最后已保存 batch、本次耗时、速率、阶段 ETA 和已有指标。验证使用独立局部计数，清楚标识固定子集或全量验证。
- `run_samples_s` 为本次新增训练样本除以从入口启动起的整体墙钟耗时，包含初始化、编译、验证和保存。恢复前累计样本不进入分子。
- `train_samples_s` 使用本次近期训练窗口的实际新增样本与耗时，包含读取、解码和训练，排除显式验证/保存区间。即使指标窗口从 checkpoint 恢复，速度窗口也不能使用恢复前的样本计数；首次窗口可能包含编译，须说明。
- ETA 只估当前 epoch 剩余训练数据处理时间，或当前验证剩余处理时间，不承诺全部剩余 epoch 的结束时间。没有足够速度依据时显示 unknown；验证期间不推进训练进度。
- 阶段计时采用单调时钟。运行耗时、速度、ETA 不写入训练 checkpoint 或预计算进度 JSON，不新增独立性能恢复文件。
- 训练指标保留在设备上累计，仅在日志/TensorBoard/保存所需边界取得 CPU 值并复用。保存前确保未结束窗口准确；不照搬当前每批转列表的统计开销，不为进度统计新增逐批 GPU profiling 或强制同步。保留必要的输入错误检查，不把性能要求解释为忽略错误。
- 保存消息区分初始化、周期、epoch 等实际用途。失败不能产生虚假保存或最终完成消息；运行日志本身不是恢复凭据。

### I9. 普通 mjai 推理

- 只加载新 Conv2d checkpoint，读取足以构造 Brain/DQN 的元信息及权重，不实例化训练优化器、AuxNet 或数据集，不恢复训练游标。完整训练 checkpoint 是唯一必要模型产物。
- 保持现有 Rust Bot/PlayerState、观测和合法动作接口，经 MortalEngine 得到动作，继续使用 mjai 逐行 JSON 协议和玩家 ID 0..3。
- 默认 CPU/FP32，设备与 GPU AMP 可配置；CPU 关闭 AMP。使用 eval/inference_mode 的 eager 执行，实际 batch 由请求决定，不套用训练固定 batch 或编译/Graph 策略。
- 普通决策保持贪心、quick_eval 与和牌规则保护的现有行为。stdout 仅输出协议响应并及时刷新，诊断信息走 stderr。未知或旧 checkpoint 格式明确报错，不自动迁移。

### I10. 独立一对三对局评测

- 双方由配置明确指定新 Conv2d checkpoint。挑战者占一席、对手占三席；调用现有 OneVsThree，按每个 seed 四个座位轮换计数。训练内的主策略离线验证不触发对局评测。
- 默认总场次 400、单批 64，分别对应 100 个 seed 与每批 16 个 seed。`seed_start=10000`、`seed_key=0x2000`，均可配置。总场次与单批场次必须是 4 的正倍数，拒绝非法值；按连续种子区间分批，末批只处理剩余完整种子组。
- 双方默认 cuda:0、FP16 AMP、eager、贪心、quick_eval 开启、和牌规则保护开启。双方设备、GPU AMP 与保护可分别配置，CPU 使用 FP32；Rust/PyTorch 线程可配置，初始采用库默认。结果记录实际生效设置。
- 对局批大小控制单次 Rust 调用驻留的对局数，不等于网络推理 batch。关闭牌谱写盘也不会消除现有 Rust 实现持有内存牌谱的成本，不据此承诺固定内存上限。
- 批内使用现有 Rust 进度条，每批完成后输出累计场次、一至四位次数和比例、平均顺位及按 `[90,45,0,-135]` 计算的平均顺位点。所有排名均从挑战者视角计算；顺位点不等同于牌桌原始得点或训练局奖励。
- 每次调用创建独立结果子目录，保存参数、双方模型来源及可用元信息、种子范围、已完成场次、累计结果与完成状态。每个完整批次成功后更新结果，最后一次才标为完成；避免失败写入破坏上次完整结果。
- 默认不保存完整牌谱，提供显式开关保存到本次运行范围内。不得覆盖历史评测目录，也不自动复制双方完整 checkpoint。
- 中断或失败只保留已完成完整批次的部分报告，不将正在执行的批次纳入结果。本期不做自动断点评测，重新启动创建新的运行。
- 固定 seed 固定发牌设置和座位覆盖，不承诺跨设备、精度和分批方式逐局位级一致。400 场是有限初评默认，不代表已找到最优吞吐或足以显著区分细小强度差异。

## Testing Decisions

- 沿用整体确认稿已确认的验收边界，以公开迁移/训练运行操作为主要测试接口：输入可控 chunks 与完整源 checkpoint，观察模型输出、训练后的 checkpoint、样本进度、TensorBoard 与终端日志。推理和评测通过各自入口验证协议与结果。共享模型的等价映射采用直接张量前向/梯度对照；不为每个私有辅助函数增加独立测试接口。
- 测试只约束可观察行为、数据契约与恢复语义，不绑定内部模块拆分、日志空格排版或某次运行的精确耗时。沿用既有 unittest、临时目录、小型标记数据集、固定随机种子和受控失败注入方式。
- 参考既有 reader 的两级乱序/跨块/尾 batch/按样本恢复测试、训练的初始保存及中断恢复测试、验证先于提交与失败保留旧状态测试，以及三个入口使用隔离真实牌谱副本的集成测试。扩展这些行为模式，不把导入旧运行模块作为新链路测试前提。
- **模型映射**：使用旧模型与迁移后新模型独立对照 FP32 前向、合法动作 Q、辅助预测、梯度及一次同 batch 优化更新；检查所有卷积维度、注意力归约、展平顺序、BN 统计/冻结及衰减组。结构转换的张量值和状态归属应精确对应，浮点算子结果采用有依据的容差；不得要求 1024 与 2048 的训练轨迹相同。
- **完整迁移**：源状态包含非零动量、非零 BN 统计、实际 optimizer step、AMP 和 RNG、非零样本游标及部分指标窗口。验证保留项、唯一清空项、源文件未改写、目标契约、源格式拒绝和非空目标拒绝；迁移本身不得消费样本或更新模型。
- **数据顺序**：标记样本覆盖一批跨多个 chunk、chunk 中间恢复、chunk 边界恢复和末尾小 batch。新读取序列须等于旧读取规则在同一游标后的后缀，改变 batch 后无遗漏/重复；不能只验证总数量。
- **从头与恢复**：验证初始 checkpoint 在首次更新前存在；正常中断恢复保留全部状态和指标窗口；扩大目标 epoch 可以继续，已完成启动不清理目录。验证错误格式、损坏状态和不兼容配置不会变成从头训练或覆盖原文件。
- **恢复效果**：用同格式、同 batch、同种子的小任务比较连续运行与中断恢复后的样本序列、进度、模型和优化状态。CPU 可做小型模型/迁移对照，不能用 CPU 冒烟替代固定 CUDA 优化组合验收；GPU 浮点结果按运行环境确定合理容差。
- **真实优化组合**：在 CUDA 上组合测试 Conv2d、channels_last、静态编译、reduce-overhead 和 batch 2048，覆盖完整 batch → 多轮验证 → 真实尾 batch → 下一完整 batch，以及保存后重启。确认存在真实参数更新、完整路径未静默降级、指标有限、BN/AMP/优化器步数没有隐含预热推进。有限验收覆盖至少三次验证切换以复查此前的第二轮停顿现象。
- **验证与提交**：检查固定子集身份、截断后的真实小 batch、按样本加权指标、全量验证、训练模式恢复与无训练状态更新。验证 epoch 尾部与周期重合只提交一次；注入验证失败和保存失败后，旧 checkpoint 与最后保存日志位置均保留。
- **计数与周期**：使用累计 batch 123456 等非整周期恢复点验证 123500 的首次触发；检查迁移不减半历史 batch，累计样本不按新 batch 倒推，AMP 跳过更新时批次数与样本消费仍按实际处理记录。
- **日志与 TensorBoard**：覆盖首次启动、迁移后恢复、模型准备/首批、周期、验证、保存、尾部与已完成启动。检查即时 flush、训练与验证计数分离、已处理与已保存位置分离、终端与事件文件指标一致、累计 batch 横轴及 purge 边界。
- **速率和 ETA**：通过受控时间与工作量验证本次增量口径、恢复窗口、编译首窗、验证/保存排除范围、unknown 与阶段剩余量；不依赖真实机器速度断言固定值。确认计时不进入持久化状态，也不引入逐批指标转 CPU。
- **新模型加载与 mjai**：在没有训练数据集的隔离环境中加载新 checkpoint，验证 CPU/FP32 和可用 GPU/AMP，运行有限真实 mjai 事件流，检查响应均为合法协议 JSON、动作受 mask 约束、诊断不混入 stdout；旧格式拒绝，模型加载不依赖完整训练环境配置。
- **一对三编排**：用可控 arena 结果验证连续 seed、四座位换算、末批、非法场次数、双方配置、累计排名和平均顺位点。验证独立目录、逐批结果、可选牌谱和中途失败留下未完成报告；使用有限真实对局确认 Rust/引擎/新模型接通，不能只依靠模拟结果。
- **配置与入口**：验证 TOML 默认值、必要键和不合法值，验证从仓库根目录、显式配置路径启动；新入口不依赖筛选/奖励配置，也不错误继承预计算线程。涉及公共组件时运行受影响的现有回归，确认旧训练与 chunk 消费兼容。
- **有限性能验收**：正式实现使用相同选定 checkpoint、真实 chunk 输入和可比数据区间，对照旧链路与新组合。分别报告首次编译成本、稳定训练段吞吐、包含验证/保存的本次整体速度、主机峰值 RSS、PyTorch allocated/reserved 峰值和整卡显存观察，区分各指标口径。只在隔离实验中测量，不给普通训练加入持续 profiler。
- 性能测试按候选顺序执行，避免多个 GPU 实验相互争抢；不把显存占满、固定 1.83 倍收益或固定 6.71 GiB 作为自动通过门槛。若正式结果与原型差异明显，应先解释和定位，不能以历史数字代替验收。
- 测试仅使用有限输入、临时/隔离输出与只读源状态；不覆盖正式 checkpoint、chunks 或对局报告。长训练、生产迁移切换与全量评测不作为普通自动测试；环境不足的验收明确列为未验证，不能报告为通过。

## Out of Scope

- 改动筛选/预计算语义，重建 chunks、重新训练顺位预测模型或重新计算冻结奖励。
- 修改 libriichi 的观测、动作、规则或对局实现；本期复用现有接口。
- 新推理/评测加载旧 Conv1d 或原通用 Mortal checkpoint；迁移任意原通用格式；Conv2d 逆向迁移和额外推理权重导出。
- 删除旧训练链路、向旧入口回填进度日志、让新训练依赖旧训练运行模块。
- 复盘/GRP 模式、Akochan 评测、旧 TestPlayer 的训练内置对局、在线 TrainPlayer；自动将独立对局评测插入离线训练周期。
- 推理专用编译/CUDA Graph、多卡或多进程训练、梯度累积、BF16、fused AdamW、改变模型宽深/冻结策略或学习率计划。
- GPU 常驻整块、额外多进程预取、异步 checkpoint、融合解码 kernel、整体迁移磁盘数据等未经本轮选择的性能方向。
- 对局评测的详细和率/放铳率等牌谱统计、自动断点恢复、自动复制模型快照。
- 专用后台启动/托管/监视/重启工具，阻塞调用内的心跳，日志数据库和持久化速度/ETA。
- 源码哈希、逐文件内容哈希、猜测式 checkpoint 升级或损坏状态自动修复。
- 自动修改正式运行配置、停止或切换当前训练；无限网格实验或无期限性能监视。本规格的编写不执行迁移、推理或对局。

## Further Notes

### 已确认的放置位置与操作约定

以下是本功能约定的代码落点，尚未创建对应实现；配置与命令将在实现文档中作为可运行用法提供。

| 职责 | 位置与入口约定 |
| --- | --- |
| 现有训练 | `mortal/precompute_pipeline/train/`，保持现有入口 |
| 新优化训练、迁移、日志、离线验证 | `mortal/precompute_pipeline/train_optimize/`；`train.py` 为训练入口，`migrate.py` 为显式迁移入口 |
| 普通 mjai | `mortal/precompute_pipeline/inference/`；`inference.py` 为协议入口 |
| 独立一对三 | `mortal/precompute_pipeline/evaluation/`；`evaluate.py` 为评测入口 |
| 多入口共享模型与加载 | `mortal/precompute_pipeline/common/`；不把单入口辅助逻辑集中到这里 |
| 新训练状态 | 配置指定的独立 `artifacts` 子目录中的 `latest.pth`，TensorBoard 位于同一产出目录 |
| 评测结果 | 配置指定根目录下每次新建的独立运行子目录，结果文件为 `result.json` |

入口均使用显式 `--config`；迁移另接收 `--source-checkpoint`，从新训练配置读取目标目录；协议入口另接收位置参数玩家 ID。各新入口提供各自所需的 TOML 示例，配置放在训练产出目录之外。模型、损失、优化器和数据设置优先沿用既有名称；线程配置按入口实际用途提供，明确区分 `compile_threads`、`torch_threads` 与 `rayon_threads`，不将编译进程数与算子/Rust 并行线程混为一谈。训练不重新展开牌谱，Rayon 线程数不是训练数据加载 worker 数。

文档中的操作顺序为：从 `~/Mortal` 准备新训练配置 → 对选定旧完整 checkpoint 显式迁移 → 用新训练入口恢复 → 按需独立调用推理或评测。迁移说明必须提醒源权重选择以实际切换时的最新完整提交为准，不能把早期实验快照当作生产最新状态。实际训练切换的执行时间与授权由后续用户指令决定。

### 性能证据及限制

- [2026-10-05 性能报告](../train-performance-20261005/report.md) 记录了 Ryzen 7 9700X、RTX 4090、WSL 可见约 15.2 GiB 内存环境下的 42 个临时案例，其中 41 个完成，6144 batch 压力案例主动停止。这里不把历史进程 PID、训练位置或环境版本当作当前实时状态。
- 基线真实 reader 训练段约 10.9k 样本/秒；四项组合在 batch 2048 下测得约 20,032 样本/秒、6.71 GiB PyTorch reserved 峰值，测量段有 180 次实际更新。该速度不含首次编译、周期验证及保存，reserved 也不等于整卡总显存或主机内存。
- 完整多轮验证/尾 batch 的另一组实验使用 batch 1024 且没有布局改造，不能合并为最终四项组合已经通过完整续训验收。历史原型还使用固定 Torch seed 与额外预热，不能直接作为正式恢复逻辑。
- 不承诺固定吞吐、显存上限、总完成日期或棋力提升。batch 改动可能影响收敛；固定离线验证和独立对局评测提供观察手段，不能将单次速度提升解释为模型效果已验证。
