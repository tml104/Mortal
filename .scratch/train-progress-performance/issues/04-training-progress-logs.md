# 04: 展示训练全阶段进度、保存位置与阶段 ETA

**What to build:** 使用者直接运行新训练入口或查看重定向输出，就能知道当前阶段、样本进度、可恢复位置、速度和 ETA；日志与 TensorBoard 使用同一份指标，且不会把未保存工作显示为已保存。

**Blocked by:** 03 — 从迁移或中断位置续训并按周期验证保存。

**Status:** ready-for-agent

实施状态：2026-10-08 已完成。

**规格覆盖：** I8，以及 I5/I7 的保存边界、指标口径和恢复行为。

- [x] 新训练输出单行 key=value 并立即 flush，覆盖启动/恢复、模型准备、首批开始/结束、训练、验证开始/进度/结束、保存成功、epoch/总完成和已完成后启动。
- [x] 启动报告生效配置与恢复基线；只有首个真实 batch 执行成功后才报告首批完成，不能在编译包装器返回时宣称懒编译已经结束。
- [x] 训练周期跟随累计 batch 日志边界，验证按局部 batch 使用相同间隔；阶段事件即时输出，尾部补齐，不增加阻塞调用内的心跳线程。
- [x] 包含当前/目标 epoch、轮内样本数/总数/百分比、累计样本和 batch、最后保存 batch、本次耗时和既有指标；区分验证局部计数、训练进度与最后完整提交位置。
- [x] 整体速度以本次新增训练样本除以入口启动以来耗时，包含准备、编译、验证和保存；近期训练速度包含读取/解码/训练，排除明确验证/保存区间，首窗可能含编译并有说明。
- [x] 恢复前样本量不进入本次速度分子；恢复的指标窗口可继续，但速度窗口重新累计。ETA 只估当前训练或验证阶段，缺少依据时显示 unknown。
- [x] 使用单调时钟，耗时/速率/ETA 只存在于运行展示；不增加 checkpoint 或预计算进度字段，不新增逐批 GPU 同步或持续 profiler。
- [x] 终端与 TensorBoard 复用同一次 CPU 指标提取，明确窗口均值与验证累计均值；补齐日志不意外清空正常恢复的指标窗口。
- [x] 只有原子保存成功才推进已保存位置和打印成功消息；验证/保存失败不出现虚假完成，即使训练样本已经到 100% 也不能跳过待完成阶段。
- [x] 通过公开训练操作捕获日志和事件文件，用受控时钟及提交失败检查速率、恢复、flush、尾部与完成边界；断言字段含义，不固定无关排版和真实耗时。
- [x] 补充日志字段及速度/ETA 的用户说明，包括首批可能长时间阻塞、重定向用法和保存进度区别；不修改旧训练日志行为。

**独立验收：** 一次有限的新训练恢复过程展示完整训练/验证/保存阶段；另以受控时间和失败用例证明速度不混入历史工作、保存消息与真实 checkpoint 一致。
