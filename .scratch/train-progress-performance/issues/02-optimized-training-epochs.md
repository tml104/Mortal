# 02: 从预计算样本完成优化训练与 epoch 离线验证

**What to build:** 使用者在独立新目录从头启动优化训练后，能够按既定乱序消费已有 chunks，使用四项优化完成真实参数更新，保留尾 batch，在每轮全量离线验证后保存原生 checkpoint，并在 TensorBoard 观察训练和验证指标。

**Blocked by:** 01 — 显式迁移旧主策略 checkpoint 为原生 Conv2d 状态。

**Status:** ready-for-agent

实施状态：2026-10-08 已完成。

**规格覆盖：** I1–I5、I7 中的数据消费、从头训练、优化执行、指标及 epoch 验证提交行为。

- [x] 提供独立训练入口，使用上一票确定的新配置和公共模型；不导入旧训练运行模块，复用稳定公共 codec/数据描述，不重新展开牌谱或计算奖励。
- [x] 新读取编排保持旧派生种子算法、随机数生成器、chunk 乱序及块内乱序；单块 CPU 预取可配置，按 batch 在目标设备解码，跨多个 chunk 组批且保留所有样本。
- [x] 完整 batch 默认 2048，使用静态编译、reduce-overhead/CUDA Graph 与 Conv2d/channels_last；尾 batch 使用同一组原始权重的 eager 路径，不填充、不丢弃、不复制模型状态。
- [x] 训练和验证的完整 batch 都标明 CUDA Graph 步边界，避免 replay 覆盖仍待消费的输出；编译失败直接报错，不新增第三套纯 eager 生产训练模式。
- [x] 保持 Brain、DQN、AuxNet、FP16 AMP、损失定义和 AdamW 分组语义；默认配置与规格一致，batch、编译线程和必要运行参数可配置，编译线程默认 2。
- [x] 不存在 checkpoint 时仅在合法训练专用产出范围内按从头约定清理，随机初始化并在首个更新前保存主种子及初始状态；配置、数据和源权重受到既定路径保护。存在状态时不能误入清理流程。
- [x] 首批承担真实懒编译/捕获成本并正常计数，不做额外隐藏更新；累计样本按实际数量增加，累计 batch 每处理一批增加一次，遵守 AMP 可能跳过参数更新的语义。
- [x] 支持可配置的总 epoch，默认目标 30；每轮结束按固定验证顺序执行全量 val，按真实样本量加权，处理验证尾 batch，正确恢复训练模式和 BN 冻结设置。
- [x] 全量验证成功后原子保存对应完成状态，包含完整模型、优化器、AMP、随机数、数据位置和未输出指标窗口；验证或写入失败不覆盖上一次完整状态。
- [x] 按累计 batch 默认每 50 批写入既有训练指标与学习率，epoch 验证写入最终加权指标；设备上累积统计，到输出或保存边界才提取 CPU 值，避免照搬逐批转列表开销。
- [x] 配置示例与最小启动说明随本票交付。中途恢复、固定子集周期提交由 03 完成，详细终端日志由 04 完成，不将本票标记为完整功能最终验收。
- [x] 标记样本验证两级乱序、跨块 batch 和尾部数量；有限 CUDA 测试通过公开训练运行覆盖真实更新、训练到全量验证再到下一轮完整 batch，核对 checkpoint 和 TensorBoard，不用纯 CPU 测试代替 CUDA 组合验证。

**独立验收：** 在隔离的小型完整数据集上从头训练至少一个 epoch，产生初始状态、真实参数更新、尾 batch、全量验证和轮末 checkpoint；可重新加载产物查看模型与完成进度。

**边界：** 本票只把新训练的从头运行闭环打通。中途续训不通过临时自动重置、跳样本或权重初始化替代，统一由下一票完成。
