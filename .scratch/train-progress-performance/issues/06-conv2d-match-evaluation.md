# 06: 对两个新模型执行分批一对三评测并保存结果

**What to build:** 使用者指定两个新格式模型后，运行有限、可配置的一对三评测，看到批内及累计进度，并在独立目录得到逐批更新的基本排名报告；中断保留已完成部分，牌谱可选择保存。

**Blocked by:** 01 — 显式迁移旧主策略 checkpoint 为原生 Conv2d 状态。

**Status:** ready-for-agent

实施状态：2026-10-08 已完成。

**规格覆盖：** I1、I5 的公共加载边界及 I10 的独立对局评测。

- [x] 提供独立评测入口、配置解析与示例，双方均由公共加载能力读取新 Conv2d checkpoint，复用 MortalEngine 与现有 OneVsThree；不依赖普通 mjai CLI 或训练循环。
- [x] 默认 400 场半庄、每批 64 场、seed_start=10000、seed_key=0x2000，均可配置；总场次和批次均为 4 的正倍数，非法值报错，不静默舍去余数。
- [x] 按连续 seed 区间执行，每 seed 四座位轮换；不足一批时处理剩余种子组，确保实际完成场次与配置一致。对局批次不被误用为神经网络固定 batch。
- [x] 双方默认 cuda:0、FP16 AMP、eager、贪心、quick_eval 和和牌规则保护；设备、AMP、保护可分别配置，CPU 为 FP32。必要 Rust/PyTorch 线程可配置，未配置时使用库默认。
- [x] 批内使用现有 Rust 进度条，每批输出挑战者累计场次、四档排名次数/比例、平均顺位及按既定顺位点计算的平均顺位点。
- [x] 每次运行新建独立结果子目录，保存配置、生效执行设置、模型来源及可用元信息、种子范围、累计结果和完成状态；不清空历史目录或复制整份模型。
- [x] 每个完整批次后可靠更新结果，最终批次完成后才标记完成；中途失败保留前面完整批次的未完成报告，写入失败不破坏已有报告。不实现自动续跑。
- [x] 默认不保存牌谱，显式开启时仅写入本次运行范围；不额外解析详细和率/放铳率，不修改 Rust 的内存日志行为。
- [x] 用可控 arena 返回值核对种子分批、尾批、计数及均值，并覆盖非法参数、历史目录保护、可选牌谱和中途失败；运行有限真实对局确认新模型与 Rust 环境接通。
- [x] 提供配置和报告说明，明确关闭写盘仍有内存牌谱成本、固定 seed 不保证跨设备/精度/分组位级相同、400 场只是初评默认。

**独立验收：** 使用两份迁移或构造的新格式 checkpoint 完成至少两个有限评测批次，得到可独立复核的最终结果；另验证中断只保留前一完整批次。无需通过 05 的 stdin/stdout 协议入口。
