# 03: 从迁移或中断位置续训并按周期验证保存

**What to build:** 使用者将迁移产物或新训练的完整 checkpoint 交给正常训练入口后，从准确的样本位置继续；周期固定子集验证和保存按历史累计 batch 延续，普通重启不会丢失优化历史或统计窗口。

**Blocked by:** 02 — 从预计算样本完成优化训练与 epoch 离线验证。

**Status:** ready-for-agent

实施状态：2026-10-08 已完成。

**规格覆盖：** I4–I7 的迁移后续训、正常恢复、周期验证、提交和 TensorBoard 连续性。

- [x] 正常启动加载新格式完整 checkpoint，恢复模型、AdamW、AMP、CPU/CUDA RNG、主种子、数据身份、epoch、样本位置、累计计数、最近验证及未输出指标窗口；首次真实步骤前随机状态正确恢复。
- [x] 保持旧规则生成的逻辑样本序列，从已消费样本数直接定位，支持 chunk 内与 chunk 边界恢复；迁移时 batch 1024 改为 2048 只重新分组剩余样本，不跳过或重复已提交样本。
- [x] 历史累计 batch 不减半，累计样本不由新 batch 乘积倒推；迁移输出已清空的展示窗口从零开始，普通同格式恢复则继续其未完成窗口。
- [x] 默认每累计 500 批执行固定顺序前 131072 个验证样本并保存，验证种子默认 0，小验证集使用全部可用样本；默认每累计 50 批写训练指标，均保留可配置性。
- [x] 从 123456 等非周期点恢复时，下次默认日志与周期验证保存发生在 123500，不按本次启动重新计周期。
- [x] 固定子集截断造成的小 batch 使用实际数量和 eager 路径；验证不更新模型、BN、优化器及训练游标，结束后正确恢复执行模式。
- [x] 轮末与周期重合时只执行一次全量 epoch 验证及提交；验证或保存失败仅保留上次完整恢复点，已读/预取而未提交的样本不变成持久进度。
- [x] TensorBoard 横轴仍为累计 batch，恢复 purge 边界为已保存 batch 加 1；不复制旧事件目录，不增加样本横轴副本，训练指标窗口的跨 epoch 语义不改变。
- [x] 目标 epoch 是累计总目标；已完成启动明确返回完成状态，提高总目标可继续。普通恢复拒绝旧格式、损坏及不兼容语义，运行参数变化不能触发隐式初始化。
- [x] 小型同配置任务比较连续与中断恢复的样本序列、进度、模型和优化状态；单独验证迁移后的状态恢复，不能仅验证新格式自恢复。
- [x] 在有限 CUDA 任务中覆盖至少三次周期验证切换、训练尾 batch、下一完整 batch 与保存重启；通过失败注入检查原子提交边界和旧产物保护。
- [x] 补充周期、恢复和迁移后启动说明，明确 batch 改动可能改变优化轨迹，不承诺与原 batch 训练逐位相同。

**独立验收：** 同一隔离数据集完成“迁移 → 新入口消费剩余样本 → 周期保存 → 停止 → 重新启动 → 完成 epoch”，可独立核对样本后缀、计数、状态和验证结果。

**边界：** 不增加自动旧格式升级、逆向迁移、额外随机排列持久化或后台重启工具。
