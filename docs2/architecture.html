01

整体架构

先看两条相互连接的主线：对局时将事件变成动作，训练时将牌谱变成可学习的决策样本。在线模式再把模型更新与自对战连成闭环。

规则与学习的边界

Rust 输出观测与合法动作 mask；Python 输出动作编号和 Q 值；Rust 再映射回 mjai 事件。

两个不同的预测任务

主策略判断“此刻做什么”；GRP 判断“四人最后各排第几”。两者没有共享主干。

文件与 TCP

数据和模型存于牌谱、chunks、checkpoint 与日志；在线进程通过 TCP 交换参数和 replay，无数据库依赖。

02

Rust 侧架构

libriichi 是规则核心，也是 Python 扩展。内部的 agent 与 algo 等模块不等于同名 Python 子模块；对外导出由 lib.rs 统一注册。

一次 Bot 决策如何经过 Rust？

Bot.react(line) 解析 EventWithCanAct，执行 PlayerState.update()。仅在允许响应且存在可行动作时，调用代理的 set_scene() / get_reaction()。代理按模型版本编码观测，收集 batch，回调 Python 的 react_batch()，然后把动作编号转换成 EventExt，序列化为 JSON。

enable_quick_eval 与规则和牌保护会影响具体决策分支；图中展示需要执行神经网络评估的主路径。杠的牌种二次选择也由 Rust 代理协调。

Brain / DQN 的 v1–v4 差异与 Oracle
版本观测形状（不含 B）Brain 输出 / 残差布局DQN 头
v1938 × 34μ、logσ 各 512；ReLU / post-activation两个 Linear：512 → 1 / 46
v2942 × 341024；Mish / pre-activation双 MLP：1024 → 512 → 1 / 46
v3934 × 341024；同 v2，BN eps=1e-3双 MLP：1024 → 256 → 1 / 46
v41012 × 341024；同 v3单 Linear：1024 → 47，再拆成 1 + 46

v1 的 ResNet 输出先经 Linear(1024,512) + ReLU 再分成两个高斯参数头。推理使用 μ，或在开启 stochastic_latent 时采样。标准 train.py 的 1024 维辅助头与训练流程没有处理 v1 二元输出，应使用 v2–v4。

Brain(is_oracle=True) 支持把不可见观测沿通道轴拼接：v1 增加 211 通道，v2–v4 增加 217 通道。当前常用训练和普通推理没有启用；本页主图均为非 Oracle 路径。

替换 GRP 后，Mortal 怎样训练？ 当前实际链路

pts 是配置的一至四位效用，局奖励是相邻边界的期望效用差；steps_to_done 是按动作类型累计的折扣步数。预计算将这些结果固化后，训练 batch 不再运行 GRP。普通推理也无需把 GRP 串到 DQN 后面。
